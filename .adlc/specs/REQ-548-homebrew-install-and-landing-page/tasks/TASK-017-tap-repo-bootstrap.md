## Description

Create the public tap repo `atelier-fashion/homebrew-tap` (verified absent)
so `brew install atelier-fashion/tap/teton` has a resolvable tap and the
`bump-formula` job has a push target. Initial contents: a README explaining
the tap is machine-written by teton-code's release workflow, and a
`Formula/` directory whose formula arrives with the first `vX.Y.Z` release
(no placeholder formula that could half-install — BR-10 honesty).

## Files to Create/Modify

- `docs/homebrew-tap-setup.md` — mark the bootstrap steps as executed (repo created, secret still pending user PAT) so the runbook reflects reality

## Acceptance Criteria

- [x] `gh repo view atelier-fashion/homebrew-tap` succeeds; repo is public, MIT-licensed, description names teton-code's release automation as its writer
- [x] Tap README states: contents are generated by `teton-code`'s release workflow; hand edits will be overwritten; install command is `brew install atelier-fashion/tap/teton` (available from the first release)
- [x] `brew tap atelier-fashion/tap` succeeds against the empty tap (brew tolerates a tap with no formulae; verify locally)
- [x] No `Formula/teton.rb` exists yet — the first release writes it (a formula pointing at nonexistent artifacts must never be published)

## Technical Notes

- External side effect: `gh repo create atelier-fashion/homebrew-tap --public`.
  This is the one deliberately outward-facing step in the implementation
  phase; it is the REQ's core deliverable and is empty/inert until the first
  release renders a formula into it.
- The `HOMEBREW_TAP_TOKEN` fine-grained PAT can only be minted by the user
  (GitHub UI) — the runbook documents it; the release workflow's bump job
  will fail loudly (BR-4) if the secret is absent, which is the correct
  pre-first-release state, surfaced in docs/release-runbook.md's checklist.
