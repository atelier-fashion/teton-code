## Description

Pin `REMOTE_TOKENS_PER_WORD` (3/2) and the 2 B/token byte floor against a real
corpus tokenized once with a reference tokenizer, committed as a fixture so
CI needs no tokenizer dependency (ADR-10). The test asserts, per sample,
`max(words × 3/2, bytes / 2) ≥ tokens`, and that the fixture's recorded
word/byte counts still match the sample files (a stale fixture is red).

## Files to Create/Modify

- `crates/tetond/tests/fixtures/token_corpus/prose.txt`, `rust.rs`, `minified.json`, `paths.txt`, `base64.txt` (new) — ≥ 2 KB each; `rust.rs` a real slice of this repo; `paths.txt` real `find`-style output with long absolute paths; `base64.txt` 4 KB of base64; `minified.json` a minified tool-result shape. No secrets (LESSON-462).
- `crates/tetond/tests/fixtures/token_corpus/token_counts.json` (new) — `[{ "file", "words", "bytes", "tokens", "tokenizer": "o200k_base" }]`, generated by the script.
- `tools/token_corpus/count.py` (new, stdlib + `tiktoken`; documented in its header) — recomputes counts; `--check` exits non-zero if the committed json differs.
- `crates/tetond/tests/token_corpus.rs` (new) — reads the fixture relative to `CARGO_MANIFEST_DIR`; recomputes `words` (whitespace split — **the same rule as `approx_tokens`, context.rs:1476-1478**) and `bytes`; asserts recorded counts match; asserts `max(words * 3 / 2, bytes / 2) >= tokens` for every sample and names the sample on failure; asserts non-vacuity as: the prose sample is covered by the words guard alone (`words × 3/2 ≥ tokens`) and at least one dense sample (Rust / paths / base64) is NOT (`words × 3/2 < tokens`) — proving the byte guard is needed — without requiring any sample to fail the combined bound; records each sample's measured bytes/token in the test output and TASK-191's runbook (so the 2 B/token floor can be revisited with evidence). Reads the constants from `tetond::harness::budget` when TASK-182 has landed; if it runs first, use literals with a `// pinned to budget.rs` comment and TASK-192 swaps them.

## Acceptance Criteria

- [ ] `cargo test -p tetond --test token_corpus` green; weakening either constant (3/2 → 1/1, or bytes/2 → bytes/4) makes a sample fail and the message names it.
- [ ] `python3 tools/token_corpus/count.py --check` passes on the committed fixture; the script's header says how to regenerate and which tokenizer/version.
- [ ] No new Cargo dependency.
